# Публикация расширения в Chrome Web Store

Зачем: коллеги ставят расширение в один клик из магазина, без «Режима разработчика» и без zip-архивов,
а обновления приходят сами (Chrome проверяет их несколько раз в день).

Что лежит в этой папке:

| Файл | Что это |
|---|---|
| `weblate-extension-store.zip` | архив для загрузки в магазин (собирается `python3 bookmarklet/build.py`, без поля `key`) |
| `screenshots/*.png` | скриншоты 1280×800 для карточки |
| `promo-440x280.png` | маленькая промо-плитка (обязательна) |
| `listing.md` | тексты для карточки: название, описания, обоснование разрешений, ответы про данные |
| `privacy-policy.md` | политика конфиденциальности (нужна ссылка на неё) |

Сама публикация делается вручную из аккаунта Google, у Claude нет к нему доступа.

## Шаги

1. **Аккаунт разработчика.** Зайди на https://chrome.google.com/webstore/devconsole под рабочим Google-аккаунтом
   (лучше общим, например localization@…, чтобы расширение не было привязано к одному человеку).
   Регистрация стоит **$5 один раз**. Нужно подтвердить почту.
2. **Новый элемент** → «Добавить» → загрузи `store/weblate-extension-store.zip`.
3. **Вкладка «Описание в магазине» (Store listing):** скопируй тексты из `listing.md`,
   категория — «Инструменты» (Tools, раздел Workflow & Planning), язык — русский,
   значок подтянется из архива, добавь `promo-440x280.png` и скриншоты из `screenshots/`.
4. **Вкладка «Конфиденциальность» (Privacy):** единое назначение, обоснование каждого разрешения,
   «удалённый код — нет», галочки про данные — всё есть в `listing.md`.
   Ссылка на политику: выложи `privacy-policy.md` туда, где её можно открыть без входа
   (Google Документ с доступом «всем, у кого есть ссылка», Notion или GitHub Pages) и вставь ссылку.
5. **Вкладка «Распространение» (Distribution) → видимость.** Варианты:
   - **Private → «Доверенные тестировщики»**: только для перечисленных e-mail (Google-аккаунты коллег).
     Самый простой вариант для небольшой команды.
   - **Private → только домен** (если почта компании на Google Workspace): видно всем с адресом @компании,
     чужим не видно. Админ Workspace может ещё и поставить расширение всем принудительно.
   - **Unlisted (по ссылке)**: в поиске нет, установить может любой, у кого есть ссылка.
   - Public — не нужно.
6. **«Отправить на проверку».** Проверка обычно занимает от нескольких часов до нескольких дней.
   Если попросят пояснений по разрешениям — ответы в `listing.md`.
7. После одобрения раздай коллегам ссылку на страницу расширения → «Установить».

## Обновления

1. Подними `version` в `extension/manifest.json` (например 1.3.0 → 1.3.1).
2. `python3 bookmarklet/build.py` — пересоберёт `store/weblate-extension-store.zip`.
3. В консоли разработчика → пакет → «Загрузить новый пакет» → «Отправить на проверку».
   После проверки обновление само придёт всем.

## Важно про переезд с zip на магазин

- У версии из магазина **другой ID**, чем у распакованной (у неё свой ключ). Поэтому настройки
  не переедут сами: в старой версии ⚙ → «Сохранить настройки в файл», в новой ⚙ → «Загрузить настройки из файла»,
  API-ключ Smartcat ввести заново. Старую распакованную версию после этого удалить, чтобы не было двух значков.
- Поле `key` в `extension/manifest.json` оставляем: оно нужно только для распакованной версии из zip.
  В архив для магазина оно не попадает (магазин его не принимает).
- API-ключ Smartcat в расширении не зашит и в магазин не уходит: каждый вводит его в ⚙ у себя.
